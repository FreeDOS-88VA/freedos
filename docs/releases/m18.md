# M18 — FreeDOS PC-88VA basic 2HD disk

## Validation boundary: emulator only

**This is an emulator-validated-only release (エミュレータ検証のみ).**

- **HOST PASS**: public-input-only complete clean builds, two-build byte
  comparison, M18-local host/negative tests and native x64 CI.
- **VAEG PASS**: the exact designated disk's bounded VA/VA2 boot, shell,
  edit/assemble/COM-and-MZ-run, allocation/ownership and native floppy tests.
- **DEFERRED HARDWARE VALIDATION**: hardware compatibility is not qualified;
  **no HARDWARE PASS** is claimed. A known JWASMR real-machine hang remains.

This is an experimental port, not a complete upstream FreeDOS distribution or
an assurance that arbitrary DOS software works on PC-88VA hardware. See the
[full validation report](../porting/m18-report.md) and
[archive manifest](../../images/milestones/m18/manifest.json).

## Downloads and corresponding source

The single designated disk is a native 80-cylinder, 2-head, 8-sector/track,
1024-byte/sector FAT12 2HD image. Use a **writable copy** in a supported
VA/VA2 emulator with operator-supplied licensed ROMs. No ROM, private firmware
or private guest disk is included.

The D88 and xz asset are the **same designated disk**, not alternative builds.
The source bundle is the exact public qualified implementation's host-side
source/build/license companion, **not a floppy**. It is bound to
`99a8f59a0ec7388cc16968a8814aa23bb0ba8c92`. This release changes documentation
and acceptance caveats only: disk bytes, DOS executables and component pins
remain those already host/emulator-qualified.

The disk includes FreeCOM, English/ASCII EDLIN, MORE, MEMMAP, real-mode JWASMR,
native-2HD FORMAT/CHKDSK/SYS, and COM/MZ source examples. For HELLO, read
`HELLO.DOC` and use:

```dos
JWASMR -0 -bin -Fo=HELLO.COM HELLO.ASM
HELLO.COM
```

Run HELLO **only after successful assembly**; no linker is required.
The small edit/assemble/run workflow is qualified in VAEG with **640 KiB
installed RAM**, not merely a retained firmware setting. No arbitrary
source-size promise, 512-KiB assembly PASS or 256-KiB editor PASS is made.

## Known issues — M19's first task

1. **JWASMR hangs on physical hardware before Usage appears**, including a
   no-argument invocation. This is an owner-reported failure, not an
   independently reproduced root cause or a diagnosis of defective RAM.
   Successful VAEG execution does not resolve it. **M19 must address this
   first, before SASI-data implementation**; see the
   [M19 entry task](../tasks/M19-first-task-jwasmr-hardware-startup.md).
   M18 ships the unchanged executable and makes no real-machine assembler
   compatibility claim.
2. Redirected `CHKDSK A:` output can be empty
   ([issue #12](https://github.com/nakatamaho/freedos-pc88va/issues/12)); it is
   excluded from successful filesystem-check claims.

SASI/SCSI, HDD boot, exhaustive DOS/CPU compatibility, useful in-program RAM
and instantaneous disk-workspace peaks are outside this release's validation.
M19 implementation has not started; its storage scope and M17 contracts remain
unchanged apart from the owner's startup-issue priority.

## Rebuild and licenses

For byte-identical reproduction of the attached qualified source bundle:

```sh
git clone --recurse-submodules https://github.com/nakatamaho/freedos-pc88va.git
cd freedos-pc88va
git checkout 99a8f59a0ec7388cc16968a8814aa23bb0ba8c92
git submodule update --init --recursive
make m18-toolchain
make m18-disk
make m18-accept
```

Follow the [public setup guide](../../tools/m18/DISTRIBUTION-README.md) for the
pinned toolchain and host dependencies. `make m18-disk` builds the entire disk
twice from clean allowlisted source exports, without old disks, saved DOS
binaries or private inputs. Checking out the documentation-only `m18` release
tag instead must reproduce the same D88; its source bundle records that tag's
different parent identity and is not expected to match the qualified bundle.

License references and all parent/component/toolchain identities are in the
[archive manifest](../../images/milestones/m18/manifest.json), the source
bundle and on-disk notices. Kernel/FreeCOM/EDLIN and JWasm retain their
applicable licenses; official Open Watcom 1.9 runtime source remains publicly
obtainable at the pinned URL/hash in the setup guide. The release illustration
is an owner-provided photo used with permission, not part of the DOS payload.
