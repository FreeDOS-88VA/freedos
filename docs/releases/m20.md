# M20.1 — FreeDOS 1.4 based PC-88VA disk set

## Validation boundary

**M20.1 is the designated M20 distribution. It replaces M20 (release candidate 5), which remains available at tag `m20`. It is validated on emulators, plus an owner hardware report of bounded scope.** The memory layout contract is [m20-memory-layout.md](../porting/m20-memory-layout.md) (section 7 and the M20.1 build layout).

- **HOST PASS**: public-input-only clean builds of the published revision, two-build byte comparison, a fresh-clone build, M20 host tests and acceptance, the component loader and adapter tests (only failures that predate M20.1 remain), and native x64 CI.
- **VAEG PASS** for the M20.1 system disk: startup, shell, MZ execution and file write/copy on VA2 and VA at 640 KiB, VA2 at 512 KiB with a retained 640 KiB selection, VA at 384 KiB and VA2 at 256 KiB; MEM with swapped FreeCOM; MS-DOS 4 COMMAND.COM through menu choice 2; replacing the B: disk during a session; floppy command counts against M20 with identical results. Checks carried from M20 and not re-run on M20.1 are listed in the [manifest](../../images/milestones/m20/manifest.json).
- **Not run on M20.1**: F5/F8 startup keys, the utilities and archiver disks with this system disk, non-default `PC88VA_LOADSEG`.
- **HARDWARE PASS (owner report, this scope only)**: the M20.1 system disk boots from A: on a real PC-88VA2 with 640 KB (installed and retained in backup memory) and runs `DIR` and `CHKDSK`; the owner reports noticeably faster disk access than M20 (not measured).
- **DEFERRED HARDWARE VALIDATION** for everything else: the PC-88VA, other memory sizes, other commands, disk writes, menu choice 2, the utilities and archiver disks and F5/F8 are **NOT RUN** on hardware.

M20 restarts the port on the FreeDOS 1.4 release sources (kernel `ke2043`, FreeCOM `com086`) with selectively imported changes. English only; Japanese support is planned for the next milestone.

## Downloads

Three native 80-cylinder, 2-head, 8-sector/track, 1024-byte/sector FAT12 2HD disks. Use **writable copies** in a supported VA/VA2 emulator with operator-supplied licensed ROMs; no ROM or private disk is included.

- System (A:, bootable): FreeDOS kernel with a startup shell menu — **1** FreeCOM 0.86 through KSSF (swaps itself out while a program runs) or **2** MS-DOS 4.0 COMMAND.COM (`A:\MSDOS`) — plus EDLIN, MORE, MEM, JWASMR, DEBUG, native-2HD FORMAT/CHKDSK/SYS and COM/MZ examples.
- Utilities (B:, label `M20-UTIL`): FIND, SORT, XCOPY, LABEL, MOVE, APPEND, NLSFUNC, DEVLOAD, CHOICE, DELTREE, COMP, FC, ATTRIB, TREE, REPLACE, EXE2BIN.
- Archivers and tools (B:, label `M20-ARC`): UNZIP, ZIP, GZIP (16-bit builds) and DEBUG. They need **640 KiB** installed.

## Changes in M20.1

- **Faster floppy access**: the PC-88VA disk code called the ROM floppy BIOS once per sector, so a real drive waited about one disk revolution for every sector. The loader, the kernel's read and write adapter and the common disk driver now transfer the sectors of one track in one ROM call; media recognition tries the last recognized format first instead of switching through the 2D, 2DD and 2HC modes on every check. On the VAEG emulator the same DIR and COPY commands need 98 instead of 356 floppy reads, 45 instead of 131 writes and 39 instead of 93 recalibrations, with identical results. The speed-up on real hardware has not been measured.
- **Write errors**: writes now go a track per call, as on the PC; after an error the reported count covers the completed calls. Writes are still attempted once, so a dirty buffer is never replayed on a newly inserted disk.
- **Memory**: the resident kernel is 224 bytes larger (506,976 instead of 507,216 bytes for the largest program with swapped FreeCOM). INIT, staging and carrier addresses are unchanged.
- The utilities disk is identical to M20; the archiver disk differs only in the build-date strings inside UNZIP.EXE and ZIP.EXE.

## Changes in M20 (release candidate 5)

- **ROM mouse BIOS kept**: FreeDOS replaced INT 33h with an empty handler at startup; on the VA it is the ROM mouse BIOS, which is now usable from DOS programs.
- **ROM services that would overwrite the kernel are refused**: the advanced graphics BIOS (INT 87h), the animation BIOS (INT 88h) and the V1/V2 supervisor vectors (INT 90h, 95h) use memory that holds the FreeDOS kernel; they now return with the carry flag set instead.
- The archiver disk differs from release candidate 4 only in the build-date strings inside UNZIP.EXE and ZIP.EXE.

## Changes in release candidate 4


- **FreeDOS MEM** replaces MEMMAP (`MEM`, `MEM /C`, `MEM /D`). It is FreeDOS MEM 1.11 built for the VA: conventional memory comes from DOS, not from PC BIOS calls. MEM counts the VA firmware area below 64 KiB as SYSTEM.
- **Less memory used**: the kernel no longer keeps its one-time machine initialization and milestone diagnostics resident (about 2.7 KB), and `STACKS=0,0` drops the 2 KB interrupt-stack pool. Free memory on 640 KiB (MEM /C at the prompt): **507,760 bytes** with FreeCOM (swapped), **506,352 bytes** with MS-DOS 4 COMMAND (release candidate 3: 505,008 with FreeCOM).

## Changes in release candidate 3

- **Shell menu at startup**: 1 = FreeCOM (default; Enter or 5 seconds), 2 = MS-DOS 4.0 COMMAND.COM built from Microsoft's MIT-licensed source (`A:\MSDOS`, license `MSDOS.LIC`). F5 and F8 work in the menu.
- **FreeCOM swaps by default** (`/SWAP`); batch files, redirection and pipes run without swapping. FreeCOM's long-filename support is removed. AUTOEXEC.BAT sets `PATH A:\`.
- The owner reports a boot, command execution and file write on a real PC-88VA2 with 640 KB using release candidate 1 (owner report, not a HARDWARE PASS).

## Known issues and limits

- FreeCOM does not swap in batch files, redirection, pipes or secondary shells. MS-DOS 4 COMMAND has no HELP, history or aliases and was not tested at 384/512 KiB.
- The advanced graphics (INT 87h) and animation (INT 88h) BIOS and the V1/V2 supervisor vectors (INT 90h, 95h) are unavailable under FreeDOS (carry flag set).
- Hardware untested by the project; the owner reports a boot, command execution and file write on a real PC-88VA2 with release candidate 1. Memory: 640 KiB is the qualified setting for JWASMR and the archivers; at 384 KiB JWASMR cannot start, at 256 KiB SORT, XCOPY and MOVE fail for lack of memory.
- Not ported: UNDELETE, SWSUBST, SHARE; FAT32 is off.
- The stable M18 and M19 Preview 1 kernels contain a startup-key defect (F5/F8 window wrong on VA2, absent on VA) that M20 fixes.
- Upstream FreeDOS 1.4 behavior is kept as is (not repaired), for example the UNZIP time-zone warning and GZIP 8.3 naming.
- Regression beyond scratch PC boot smoke tests was not run.

## Rebuild from public source

```sh
git clone https://github.com/FreeDOS-88VA/freedos.git && cd freedos
git checkout 0012847b5bbe742eba392df1b63842899f6f7794
git submodule update --init --recursive
make m20-toolchain
make m20-disk
make m20-accept
sha256sum dist/m20/*.D88 dist/m20/*SOURCES.tar.xz
```

The hashes must match the table above. Extraction check: `xz -dc images/milestones/m20/<file>.d88.xz | sha256sum`.
