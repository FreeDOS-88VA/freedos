# M20 release candidate 2 — FreeDOS 1.4 based PC-88VA disk set

## Validation boundary: emulator only, release candidate

**This is a release candidate (prerelease) validated on emulators only (エミュレータ検証のみ).**

- **HOST PASS**: public-input-only clean builds, two-build byte comparison, M20 host tests, byte-identity of the non-PC-88VA kernel/FreeCOM/utility builds with FreeDOS 1.4, and native x64 CI.
- **VAEG PASS**: bounded VA/VA2 boot, shell, utilities, archivers, DEBUG and startup-key checks listed in the [report](../porting/m20-report.md) and [manifest](../../images/milestones/m20/manifest.json).
- **DEFERRED HARDWARE VALIDATION**: hardware is **NOT RUN**; no HARDWARE PASS is claimed.

M20 restarts the port on the FreeDOS 1.4 release sources (kernel `ke2043`, FreeCOM `com086`) with selectively imported changes. English only; Japanese support is planned for the next milestone.

## Downloads

Three native 80-cylinder, 2-head, 8-sector/track, 1024-byte/sector FAT12 2HD disks. Use **writable copies** in a supported VA/VA2 emulator with operator-supplied licensed ROMs; no ROM or private disk is included.

- System (A:, bootable): FreeDOS kernel, FreeCOM started through KSSF (kernel swap: `CALL /S program`), EDLIN, MORE, MEMMAP, JWASMR, DEBUG, native-2HD FORMAT/CHKDSK/SYS, COM/MZ examples.
- Utilities (B:, label `M20-UTIL`): FIND, SORT, XCOPY, LABEL, MOVE, APPEND, NLSFUNC, DEVLOAD, CHOICE, DELTREE, COMP, FC, ATTRIB, TREE, REPLACE, EXE2BIN.
- Archivers and tools (B:, label `M20-ARC`): UNZIP, ZIP, GZIP (16-bit builds) and DEBUG. They need **640 KiB** installed.

## Changes since release candidate 1

- FreeCOM's kernel swap is enabled: `CONFIG.SYS` loads the shell with `SHELL=A:\KSSF.COM A:\COMMAND.COM /E:512 /P`, and `CALL /S program` frees about 64 KiB while the program runs. The M19 kswap fix series is imported (owner-approved exception; upstream issue [FDOS/freecom#189](https://github.com/FDOS/freecom/issues/189)). KSSF is qualified only for one swapped program from the interactive shell.
- DEBUG (DEBUG.COM, with DEBUG.LIC) is also on the system disk.
- The archiver disk is rebuilt (source-lock metadata only); the utilities disk is unchanged.
- The owner reports a boot, command execution and file write on a real PC-88VA2 with 640 KB using release candidate 1. This is an owner report, not a project HARDWARE PASS.

## Known issues and limits

- Swapping is not supported in secondary shells, pipes, redirection or batch files; each swap leaves the largest free block roughly 400-500 bytes smaller.

- Hardware untested. Memory: 640 KiB is the qualified setting for JWASMR and the archivers; at 384 KiB JWASMR cannot start, at 256 KiB SORT, XCOPY and MOVE fail for lack of memory.
- Not ported: UNDELETE, SWSUBST, SHARE; FAT32 is off.
- The stable M18 and M19 Preview 1 kernels contain a startup-key defect (F5/F8 window wrong on VA2, absent on VA) that M20 fixes.
- Upstream FreeDOS 1.4 behavior is kept as is (not repaired), for example the UNZIP time-zone warning and GZIP 8.3 naming.
- Regression beyond scratch PC boot smoke tests was not run.

## Rebuild from public source

```sh
git clone https://github.com/FreeDOS-88VA/freedos.git && cd freedos
git checkout 127b00db28426f314721922ff89729e75b1cbee6
git submodule update --init --recursive
make m20-toolchain
make m20-disk
make m20-accept
sha256sum dist/m20/*.D88 dist/m20/*SOURCES.tar.xz
```

The hashes must match the table above. Extraction check: `xz -dc images/milestones/m20/<file>.d88.xz | sha256sum`.
